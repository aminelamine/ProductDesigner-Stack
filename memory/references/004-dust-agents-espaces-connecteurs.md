> **Pourquoi ça marche** — l'agent n'est pas un outil qu'on ouvre mais un collègue qu'on appelle
> dans le fil (`@agent`), plusieurs dans la même conversation. Tout le travail vit dans un espace
> persistant (*pod* : conversations, tâches, fichiers, agents), et ce qu'un agent peut lire est
> fixé par l'espace, séparément de qui l'utilise. La fiche d'un agent (instructions, outils,
> usage) est à un clic.
>
> **Ce qu'on en a pris** (F-007, B · L'établi) : le dossier PDS = l'espace ; `@agent` dans le
> fil ; la fiche d'agent au clic sur le nom ; « ce que l'agent lit » dans la section Connecteurs.
> **Ce qu'on n'en a pas pris** : le constructeur d'agents (BOB, RAY, ANALYZER sont fixés), les
> modèles multiples, crédits, audit, analytics, gouvernance, hébergement. **Aucun goût visuel.**

## Observé (docs, 2026-10-24)
- Agents génériques (accès direct à un modèle) et spécialisés (créés par des collègues), parcourables ; menu « 3 points » → instructions, outils, usage.
- Espaces et groupes : permissions sur les données, les outils et les systèmes, pour les personnes comme pour les agents.
- 70+ connecteurs MCP, recherche sémantique sur la connaissance de l'entreprise ; skills et mémoire réutilisables.
- Non documenté sur les pages lues : la citation des sources, l'affichage des appels d'outils, la revue humaine des actions, les *Frames*.
