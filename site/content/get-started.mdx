# Get Started

Ship your first feature the PDS way in about five minutes. You'll install the agent system, plan a feature with RAY, approve a Quality Brief, build with BOB, and get a score from ANALYZER.

<Callout type="info">
  **Prerequisites** — Node.js 18+ and [Claude Code](https://docs.anthropic.com/claude-code) installed, inside a front-end project (Next, Nuxt, SvelteKit, Astro, or Remix).
</Callout>

<Callout type="info">
  **New? Just run `/pds`.** The [conductor](/agents/conductor) walks the whole cycle for you — it
  even interviews you to fill the context files and adapts to your level (`user_level` in `STACK.md`):
  guided for newcomers, terse for experts. The manual steps below are what it orchestrates under the hood.
</Callout>

<Steps>

### Install the stack

Run the installer at the root of your project:

```bash
npx pds-stack install
```

Answer ten questions (framework, UI library, your level, which AI tools you use, optional modules).
In under five minutes you get:

- `STACK.md` — your stack config, including the `user_level` dial
- `CLAUDE.md` — agent registry and hard constraints
- `agent-system/` — RAY, BOB, ANALYZER, the conductor flow, the Quality Brief gate, design
  resources, ADRs, spec templates, context stubs
- **Entry points for every tool you picked** — `/pds`, `/ray`, `/bob`, `/analyzer` as real commands
  in Claude Code, Cursor, Gemini CLI, VS Code / Copilot or Codex CLI
- Optional git guardrails in `.git/hooks/`

### Start the cycle

```
/pds Add a compact newsletter signup to the footer
```

That is the whole nominal path — the conductor runs the steps below and stops at each gate for
your decision. The rest of this page is what it orchestrates, and how to drive it yourself.

### Plan a feature with RAY

Open Claude Code and call the architect:

```
/ray Add a compact newsletter signup to the footer
```

RAY challenges the idea, right-sizes it (T1/T2/T3), writes a spec with a mandatory `## OUT OF SCOPE` block, and sets `statut: VALIDATED`. **Scope is frozen at that moment.**

### Approve the Quality Brief

Call the builder:

```
/bob
```

BOB does **not** start coding. It first produces a Quality Brief — visual direction, three defining words, constraints, references — and waits.

<Callout type="warning">
  This is the gate. Read the brief. If the direction is right, approve it. If not, correct it now — before any code exists. **No brief approval, no code.**
</Callout>

### Build to spec

Once you approve, BOB implements through its 6-step Ralph Loop and commits atomically after each step (`feat(N): task-title`). One feature per session — context resets before the next.

### Score & learn

Call the reviewer:

```
/analyzer
```

ANALYZER grades the feature **/20** across four dimensions (spec conformance, UX & design system, technical quality, CX) and returns a verdict:

| Score | Verdict |
| --- | --- |
| 18–20 | SHIPPED |
| 14–17 | SHIPPED WITH NOTES |
| 10–13 | REWORK → back to BOB |
| &lt;10 | RE-SPEC → back to RAY |

It also writes a learnings file — which RAY reads before your next spec.

</Steps>

## What just happened

You didn't review code hoping it had taste. You **set the direction first**, froze the scope, and let the build execute against a contract. That's the whole idea.
