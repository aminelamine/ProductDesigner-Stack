# Get Started

Ship your first feature the PDS way in about five minutes. You'll install the agent system,
approve a direction brief with BOB, frame the scope with RAY, build with BOB, and get two
verdicts from ANALYZER.

<Callout type="info">
  **Prerequisites** — Node.js 18+ and [Claude Code](https://docs.anthropic.com/claude-code) installed, inside a front-end project (Next, Nuxt, SvelteKit, Astro, or Remix).
</Callout>

<Callout type="info">
  **New? Just run `/pds`.** The [conductor](/agents/conductor) walks the whole cycle for you — it
  even interviews you to fill the context files and adapts to your level (`user_level` in `STACK.md`):
  guided for newcomers, terse for experts. The manual steps below are what it orchestrates under the hood.
</Callout>

<Steps>

### Install the stack

Run the installer at the root of your project:

```bash
npx pds-stack install
```

Answer ten questions (framework, UI library, your level, which AI tools you use, optional modules).
In under five minutes you get:

- `STACK.md` — your stack config, including the `user_level` dial
- `CLAUDE.md` — agent registry and hard constraints
- `agent-system/` — RAY, BOB, ANALYZER, the conductor flow, the direction brief gate, design
  resources, ADRs, spec templates, context stubs
- **Entry points for every tool you picked** — `/pds`, `/bob --brief`, `/ray`, `/bob --build`,
  `/analyzer` as real commands in Claude Code, Cursor, Gemini CLI, VS Code / Copilot or Codex CLI
- Optional git guardrails in `.git/hooks/`

### Start the cycle

```
/pds Add a compact newsletter signup to the footer
```

That is the whole nominal path — the conductor runs the steps below and stops at each gate for
your decision. The rest of this page is what it orchestrates, and how to drive it yourself.

### Approve the direction brief — gate ①

Call the brief half of the builder:

```
/bob --brief Add a compact newsletter signup to the footer
```

BOB does **not** start coding. It first produces the direction brief — visual direction, three
defining words, constraints, references, read from `memory/` — and waits.

<Callout type="warning">
  This is gate ①. Read the brief. If the direction is right, approve it. If not, correct it now —
  before any scope is framed, before any code exists. **Nothing is produced before this brief is
  approved.**
</Callout>

### Frame the scope with RAY — gate ②

*(Standard and System lanes only — Sketch skips straight to production, no spec file, no score.)*

```
/ray Add a compact newsletter signup to the footer
```

RAY writes the scope **against** the approved direction — right-sizes it (T1/T2/T3), writes a
spec with a mandatory `## OUT OF SCOPE` block, and sets `statut: VALIDATED`. **Scope is frozen at
that moment**, and it can no longer contradict the direction it was framed by.

### Build to spec

```
/bob --build
```

BOB implements against the approved brief (and the frozen spec, if one exists) through its
6-step Ralph Loop, committing atomically after each step (`feat(N): task-title`). One feature per
session — context resets before the next.

### Score & learn — gate ③

Call the reviewer:

```
/analyzer
```

ANALYZER renders **two independent verdicts, never averaged**: a conformance score **/20** across
four dimensions (spec conformance, UX & design system, technical quality, CX), and a binary
direction verdict — `retenue` / `refusée` — that only you render.

| Conformance | Direction | Commits? |
| --- | --- | --- |
| ≥ 18 | `retenue` | ✅ yes |
| ≥ 18 | `refusée` | ❌ no — back to DIRECTION |
| &lt; 18 | any | ❌ no — back to PRODUIRE (RAY if &lt;10) |

It also writes a learnings file — which RAY reads before your next spec — and the direction to
`memory/directions/`, retained or refused, read before the next brief.

</Steps>

## What just happened

You didn't review code hoping it had taste. You **set the direction first**, froze the scope, and let the build execute against a contract. That's the whole idea.
