# ANALYZER — Product QA & CX

**Trigger:** `/analyzer`

ANALYZER scores every feature /20 across four dimensions, enforces a release gate, and writes a learnings file after every verdict — fed back into RAY before the next spec.

## The scorecard — /20

| Dimension | Points |
| --- | --- |
| Spec conformance | 5 |
| UX & design system | 5 |
| Technical quality | 5 |
| CX | 5 |

### Mechanical deductions

Some of the score is not a judgment call. ANALYZER applies these the same way every time:

| Trigger | Deduction |
| --- | --- |
| Code-decidable criterion shipped with no assertion | −1 each on spec conformance, capped at −2 |
| `any` or `@ts-ignore` (ADR-004) | −2 |
| `dangerouslySetInnerHTML` without sanitisation | −2 + blocker |
| `console.log` left in delivered code | −1 |

ANALYZER **re-runs** BOB's assertions rather than trusting the pasted output. A criterion reported
`proven` with no assertion it can execute is recorded as unproven, not as met.

## The verdict gates release

| Score | Verdict | Route |
| --- | --- | --- |
| 18–20 | SHIPPED | — |
| 14–17 | SHIPPED WITH NOTES | → BOB |
| 10–13 | REWORK | → BOB |
| &lt;10 | RE-SPEC | → RAY |

<Callout type="warning">
  **Only ≥ 18 is committed.** "SHIPPED WITH NOTES" means accepted in substance and still handed back
  to BOB — it does not reach the branch. Below 18, ANALYZER does not commit, no exception.
</Callout>

## Produces

A verdict, a `/20` score, and a **learnings file** — patterns, anti-patterns, spec ambiguities, CX signals. RAY reads the three most recent before the next spec, so the system compounds with use.
